A1 FlashNext-RL: A System Optimization Study for Long-Horizon Agentic RL of Qwen3.8-Flash-Next

arXiv: 2610.28998 QwenAgentic RLAgent

📝 中文摘要（中英对照）：

Long-horizon agentic reinforcement learning (RL) requires both efficient rollout generation and training on long sequences. 长视野代理强化学习（ RL ）需要有效的推出生成和长序列的训练。

However, the memory requirements and model-specific operators of Qwen3.8-Flash-Next make this difficult with existing open-source implementations. 但是， Qwen3.8-Flash-Next的内存要求和模型特定运算符使得现有的开源实现很难做到这一点。

To resolve these limitations, we introduce FlashNext-RL, a model-specific RL training optimization framework based on prime-rl, with vLLM for software engineering (SWE) rollout generation. 为了解决这些限制，我们引入了FlashNext-RL ，这是一种基于prime-rl的特定模型RL训练优化框架，其中vLLM用于软件工程（ SWE ）推出生成。

Our main focus is BF16 training of the full 48-layer model on a single 8xB200 node, with the first two layers, the n-gram table, the sparse-attention indexer and the multi-token prediction head frozen. 我们的主要重点是在单个8xB200节点上对全48层模型进行BF16训练，前两层即n-gram表、稀疏注意力索引器和多令牌预测头被冻结。

We optimize host offload, gradient accumulation and the kernels for mixture-of-experts, sparse attention and the gated residual stream. 我们针对混合专家、稀疏注意力和门控残留流优化主机卸载、梯度累积和内核。

In the full-model development study, non-padding training throughput increases from approximately 395 tokens/s/GPU in the initial 32K-token configuration to 4,438 tokens/s/GPU in the optimized 131K-token configuration, with hardware matmul throughput (aka without considering the cost of attention components) increasing from approximately 20 to 213 TFLOPs/GPU. 在全模型开发研究中，非填充训练吞吐量从初始32K令牌配置中的约395个令牌/s/GPU增加到优化131K令牌配置中的4,438个令牌/s/GPU ，硬件数学吞吐量（又称不考虑注意力组件成本）从约20个TFLOPs/GPU增加到213个。

A controlled cumulative study on an 8-layer model further quantifies the contributions of individual optimizations. 对8层模型的受控累积研究进一步量化了个体优化的贡献。

Together with three inference nodes, the system supports a live SWE RL run with a target batch of 1,024 trainable rollouts and a 131,072-token context limit. 该系统与三个推理节点一起，支持实时SWE RL运行，目标批次为1,024个可培训部署和131,072个令牌上下文限制。

Over steps 5-15, an iteration takes 22.4 minutes on average, with bounded entropy and trainer-sampler mismatch KL. 在步骤5-15中，迭代平均需要22.4分钟，有界熵和训练器-采样器不匹配KL。

These results highlight the importance of tailoring RL training to the model's architecture, memory layout and kernel requirements, rather than relying only on general-purpose RL infrastructure. 这些结果强调了根据模型的架构、内存布局和内核要求定制RL训练的重要性，而不是仅依赖于通用RL基础设施。

A2 BIRD-RL: Scaling Agentic Reinforcement Learning over Stateful Data-Centric Environments

arXiv: 2610.29426 AnthropicAgentic RLAgent

📝 中文摘要（中英对照）：

While agentic reinforcement learning (RL) has emerged as a promising paradigm for training small language models (SLMs), existing frameworks are predominantly tool-centric and struggle with data-centric environments. 虽然代理强化学习（ RL ）已成为训练小型语言模型（ SLM ）的一个有前途的范例，但现有框架主要以工具为中心，并且在以数据为中心的环境中挣扎。

Specifically, applying tool-centric frameworks to stateful tasks like SQL debugging introduces severe spatial inefficiencies since proper environment isolation typically requires a separate database container per rollout. 具体来说，将以工具为中心的框架应用于SQL调试等有状态任务会引入严重的空间效率低下，因为适当的环境隔离通常需要每个部署一个单独的数据库容器。

Naively reusing databases without tracking evolving states across multi-turn interactions causes trajectory contamination and cross-trajectory interference, which severely destabilizes policy updates. 天真地重复使用数据库而不跟踪多回合交互中不断变化的状态会导致轨迹污染和跨轨迹干扰，从而严重破坏政策更新的稳定性。

To overcome these bottlenecks, we introduce BIRD-RL, a novel four-stage agentic RL curriculum that alternately enhances foundational agent reasoning and trajectory-adaptive on-policy exploration to circumvent the instability inherently associated with direct end-to-end learning. 为了克服这些瓶颈，我们引入了BIRD-RL ，这是一种新颖的四阶段代理RL课程，可交替增强基础代理推理和轨迹自适应策略上探索，以规避与直接端到端学习固有的不稳定性。

Crucially, to support this curriculum, BIRD-RL is driven by a Trajectory-scoped Persistent Execution Infrastructure, which enables safe database replica reuse while preserving trajectory isolation. 至关重要的是，为了支持该课程， BIRD-RL由轨迹范围的持久执行基础设施驱动，该基础设施可以实现安全的数据库副本重用，同时保持轨迹隔离。

This design improves spatial RL efficiency by 12.8x, successfully enabling scalable agentic RL for complex data-centric tasks without needs of Kubernettes. 这种设计将空间RL效率提高了12.8倍，成功地为复杂的以数据为中心的任务实现了可扩展的代理RL ，而无需Kubernettes。

Empirical evaluations on the BIRD-CRITIC-SQLite benchmark demonstrate that our 7B and 14B models achieve Success Rates of 44.40% and 48.00%, respectively, showing competitive performance against strong proprietary model-based agents such as Claude-Opus-4.6 Agent (48.20%). 对BIRD-CRITIC-SQLite基准的实证评估表明，我们的7B和14B模型的成功率分别为44.40%和48.00% ，与Claude-Opus-4.6 Agent （ 48.20% ）等强大的基于模型的专有代理相比，表现出竞争力。

Furthermore, BIRD-RL successfully trains unified SLMs capable of both advanced SQL debugging and generation, highlighting its broader potential for multi-objective optimization across heterogeneous, real-world data-centric tasks. 此外， BIRD-RL成功培训了能够进行高级SQL调试和生成的统一SLM ，突出了其在异构、以实际数据为中心的任务中进行多目标优化的更广泛潜力。

A3 Recursive Self-Improvement on a Budget: Scoring Code Edits Before They Run

arXiv: 2610.29121 OpenAIAnthropicRSI

📝 中文摘要（中英对照）：

A coding agent that rewrites its own scaffold has to choose which proposed edit to expand before that edit has been evaluated, and the search then has to return one agent. 重写自己脚手架的编码代理必须在评估编辑之前选择要扩展的拟议编辑，然后搜索必须返回一个代理。

Each run fits one linear readout on the parent's steering-split solve rate and eight coordinates of the proposed diff, from 96 scaffold edits labeled by four evaluations of a 16-instance fit split, and then freezes the coefficients. 每次运行拟合父级转向拆分求解率的一个线性读数和提议的diff的八个坐标，从由16实例拟合拆分的四个评估标记的96个脚手架编辑中，然后冻结系数。

HumanEval+ reserves 48 instances as the steering split and Polyglot reserves 64. HumanEval +保留48个实例作为转向拆分和Polyglot保留64。

That split scores parents and keeps an archive of four nodes. 该拆分对父节点进行评分，并保留四个节点的存档。

Huxley-G\"odel Machine selection draws a parent by Thompson sampling on the steering counts of nodes that have already been evaluated, and it expands the child that parent proposes. Huxley-G\ "odel Machine选择在已经评估的节点的转向计数上绘制Thompson采样的父节点，并扩展父节点提出的子节点。

Every method then returns the earliest evaluated node whose steering-split solve count is maximal. 然后，每个方法返回其steering-split求解计数最大的最早计算节点。

The tables report the held-out score of that node on the other 100 HumanEval+ instances and the other 145 Polyglot instances, next to the root scaffold and the calibration edit with the highest fit-split label. 这些表格报告了该节点在其他100个HumanEval +实例和其他145个Polyglot实例上的保留分数，仅次于根支架和具有最高拟合拆分标签的校准编辑。

Twelve runs of GPT-4o return a node at 87.0% on held-out HumanEval+, against 84.2% for the parent-rate ablation. 在保留的HumanEval +中， 12次GPT-4o检测以87.0%的速度返回一个淋巴结，而父速率消融为84.2%。

On that split Huxley-G\"odel Machine selection returns 85.1%, the root is at 81.2%, and the calibration-best edit is at 82.8%. 在该分割Huxley-G\ "odel Machine选择上，返回85.1 ％ ，根为81.2 ％ ，校准最佳编辑为82.8 ％。

On the same split Claude Sonnet 4.5 returns 86.6%, beside 86.5% for Huxley-G\"odel Machine selection, 85.3% for the parent-rate ablation, and 85.1% for the calibration-best edit. 在同一分割上， Claude Sonnet 4.5返回86.6% ， Huxley-G\ "odel Machine选择返回86.5% ，父速率消融返回85.3% ，校准最佳编辑返回85.1%。

A4 VeriEvolve: Evaluator-First Evolution for Tool-Using Agents

arXiv: 2610.29005 AnthropicRSIAgent

📝 中文摘要（中英对照）：

A central obstacle to self-improving agents is the absence of a reliable fitness signal for realistic stateful tasks. 自我提升智能体的一个主要障碍是缺乏可靠的适应性信号，无法完成逼真的状态化任务。

We introduce \textsc{VeriEvolve}, an evaluator-first evolution framework that constructs this missing evaluation layer before optimizing the agent. 我们引入了\ textsc {VeriEvolve} ，这是一个评估者优先的演化框架，在优化代理之前构建了这个缺失的评估层。

From task instruction, VeriEvolve synthesizes instruction-grounded challenge states and an executable evaluator that checks them. 根据任务指令， VeriEvolve合成基于指令的质询状态和检查它们的可执行评估器。

During each round of workflow evolution, the evaluator is frozen and serves as the fitness signal. 在每轮工作流程演进过程中，评估者都会被冻结，并充当健康信号。

Between rounds, VeriEvolve revises the evaluator by converting the end states of strong and weak runs into a pair of counterfactual test cases. 在两轮之间， VeriEvolve通过将强运行和弱运行的结束状态转换为一对反事实测试用例来修改评估者。

Across all 30 MCPMark Filesystem tasks, VeriEvolve constructs 30 evaluators with 141 challenge states, achieving 141/141 agreement on the generated suites and 113/122 agreement on held-out states produced by executor agents. 在所有30个MCPMark文件系统任务中， VeriEvolve构建了30个具有141个挑战状态的评估器，就生成的套件达成了141/141协议，并就执行代理产生的保留状态达成了113/122协议。

Evaluator-guided evolution increases externally verified success from 6/30 to 18/30 for GLM-5.2 and from 27/30 to 30/30 for Claude; refinement removes all three false positives that the weak executor exposes. 评估者指导的进化将GLM-5.2的外部验证成功率从6/30提高到18/30 ， Claude从27/30提高到30/30 ；细化消除了弱执行者暴露的所有三个误报。

Cross-environment studies on PostgreSQL, Playwright, Notion, and GitHub further expose complementary limits from observability, state representation, and search/execution capacity. PostgreSQL、Playwright、Notion和GitHub的跨环境研究进一步揭示了可观察性、状态表示和搜索/执行能力的互补限制。

These results show that executable evaluators can be synthesized and used to guide search when task success is observable and an external verifier is available for calibration. 这些结果表明，当任务成功可观察且外部验证器可用于校准时，可以合成可执行评估器并用于指导搜索。

A5 Correlated Failures of AI Approval Monitors

arXiv: 2610.29178 AnthropicGoogleDeepSeek

📝 中文摘要（中英对照）：

Before an AI agent takes a consequential action, such as paying, messaging or changing code, several monitors check it. 在AI代理采取相应的行动（例如支付、发送消息或更改代码）之前，几个监视器会对其进行检查。

Their verdicts are combined by aggregating scores or by counting approvals, whatever inputs the monitors share. 他们的判断通过汇总分数或通过计算批准（监视器共享的任何输入）进行组合。

Monitors that share a base model or a poisoned input, however, may fail together. 然而，共享基本模型或中毒输入的监视器可能会一起失败。

We borrow the fail-prone systems of distributed computing: lists of monitor sets that may fail together. 我们借鉴了分布式计算的易失败系统：可能一起失败的监视器集列表。

A rule is safe if it executes no bad action and live if it blocks no good one. 如果规则不执行不良操作，则是安全的；如果规则阻止不良操作，则是安全的。

We measured twelve small open-weights monitors on payment approval under two pre-registered protocols. 我们在两个预先注册的协议下测量了十二个小型开放式权重监视器的付款审批。

Without pre-registration, we also measured three closed frontier models (Claude Opus 5.5, GPT-6 Astra, Gemini 4 Argon) and the open DeepSeek-V3.2. 在没有预先注册的情况下，我们还测量了三个封闭的前沿模型（ Claude Opus 5.5、GPT-6 Astra、Gemini 4 Argon ）和开放的DeepSeek-V3.2。

Every reliable fooling of a monitor into approving a fraud came through an evidence source and reached only that source's readers. 每次可靠地欺骗监视器批准欺诈行为都是通过证据来源进行的，并且只接触到该来源的读者。

Fooling it into blocking a correct payment depended on injection resistance, a monitor's refusal to follow instructions planted in its data. 欺骗它阻止正确的付款取决于注射阻力，监视器拒绝遵循其数据中的说明。

Small models and DeepSeek obeyed such notes. 小模特和DeepSeek都遵守这样的规定。

The three closed models ignored them in all but one case, and Opus also resisted persuasion tailored to it. 除了一个案例外，三个封闭的模型都忽略了他们， Opus也拒绝了为它量身定制的说服。

On new data, a rule that counts sources instead of votes blocked 0.9% of correct payments, against 7.4% for the best counting rule, at equal safety. 在新数据上，计算来源而不是投票的规则阻止了0.9%的正确付款，而最佳计数规则为7.4% ，安全性相等。

The pre-registered worst-case test failed. 预先注册的最坏情况测试失败。

One attack left the approvers on a single source, so no rule over the twelve language-model monitors survives every measured attack. 一次攻击将审批人留在单一来源上，因此在每次测量的攻击中，都没有十二种语言模型监视器的规则。

Adding a rule engine, which cannot be persuaded, restored the condition for a safe and live rule on the measured attacks. 添加无法说服的规则引擎，恢复了测量攻击的安全和实时规则的条件。

Diversify the inputs, harden the monitors, count sources, not votes. 使输入多样化，强化监视器，计算来源，而不是投票。

A6 What the Author Wrote, What the Agent Reads: Silent Cue Loss in Enterprise Document Ingestion

arXiv: 2610.30026 OpenAIAnthropicAgent

📝 中文摘要（中英对照）：

Enterprise agents act on documents. 企业代理根据文档执行操作。

Before an agent can follow a policy, answer a compliance question or file a ticket, some ingestion layer must turn a Word file or PDF into tokens - and that layer is where an agent deployed in the wild silently loses information. 在代理可以遵循策略、回答合规性问题或提交工单之前，某些接收层必须将Word文件或PDF转换为令牌-该层是部署在野外的代理静默丢失信息的地方。

We show that one layer is lost by every mainstream converter - the meaning an author encodes in how text looks - and that the loss makes agents confidently wrong rather than visibly incomplete. 我们表明，每个主流转换器都会丢失一层-作者在文本外观中编码的含义-并且丢失会使代理自信地出错，而不是明显不完整。

We build a task from 76 real policy documents: recover the requirements the author singled out, scored against the file's own OOXML properties by a deterministic matcher with no LLM judge. 我们从76个真实的政策文件中构建了一个任务：恢复作者挑选出的要求，由一个没有LLM法官的确定性匹配器根据文件自己的OOXML属性进行评分。
